# GPU profiler artifacts

`python -m gala_sim.tools.gpu_profile_artifacts nsys --input <sqlite> --output <json>` maps detailed `gala_stage` NVTX ranges to CUDA kernels and copies. It also checks every kernel within each outer `gala_iteration:training` range and reports whether it belongs to exactly one detailed stage.

The `ncu` subcommand parses explicitly named DRAM, FP32, XU, and atomic metrics from either thread-local push/pop ranges or process-wide `gala_ncu_stage` start/end ranges. NCU CSV output must include exactly one campaign hash in its NVTX range labels; otherwise it is `failed_preflight`. For a v4 job, run `ncu-job` with the raw details CSV, plan, job index, and stage profile. Invocation jobs bind every selected launch by stable iteration/stage/call/name/block order while retaining dynamic measured grids. Range jobs require the exact configured stage calls and bind every observed launch to a signature derived from that run; no launch is omitted or multiplicity-expanded. A failed invocation binding also retains unmatched actual launches so SourceCounters diagnostics are not discarded. Export SourceCounters as CSV and pass it to the `sass` subcommand with the bound NCU JSON to classify dynamically executed SASS opcodes. NCU may export the same SourceCounters section twice for one launch; the parser consumes one or two adjacent identical sections according to launch order and preserves consecutive launches with identical kernel names and counters. Unclassified XU instructions and unsupported MUFU or atomic semantics keep the affected stage ineligible for formal weights instead of assigning an assumed neighboring operation.

NSYS 2022.4 on the validated host does not reliably trigger repeated collection from the Python NVTX push/pop range. The campaign therefore uses explicit CUDA Profiler API start/stop calls at selected iteration boundaries. This mode was validated with two ranges in one continuous process; both exported reports had 302/302 kernels uniquely assigned and zero missing or multiply assigned kernels.
