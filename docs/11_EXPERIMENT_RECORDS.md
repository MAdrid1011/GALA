# 实验记录规范

## 1. 运行身份

每次运行分配稳定的 `run_id`，并保存代码提交、模型仓库与提交、上游补丁哈希、数据清单哈希、GALA 配置哈希、消融位、随机种子、主机、CPU、GPU、显存、驱动、CUDA、PyTorch、Numba 和 Ramulator 2 版本。

首组合 input-freeze 记录还保存参考体路径、SHA-256、shape、dtype、有限值范围和全部冻结质量参数的值、单位、来源与状态。训练身份保存绝对 Python 解释器路径、完整官方命令及哈希、工作目录、解析后的参数全集、评估/保存/检查点调度、随机状态语义、训练快照哈希，以及定义这些行为的上游源码哈希；环境依赖版本必须由该冻结解释器查询。生成器必须检查实际参数、调度、解释器和 seed，发现语义漂移时拒绝生成记录；提交与各类哈希只用于审计记录，不参与通过或拒绝判断。环境快照分别记录 `CUDA_HOME`、nvcc 路径与版本、C/C++ 编译器路径与版本、PyTorch CUDA 版本，以及 NumPy、scikit-image、torchvision 和 lpips 版本，使扩展与统一指标不依赖未记录的本地默认值。

正式结果还保存开始时间、结束时间、退出状态、峰值主机内存、峰值显存、GPU 利用率分布、trace 字节数和结果文件哈希。

## 2. 运行状态

状态只允许使用 `planned`、`running`、`passed`、`failed_quality`、`failed_trace`、`failed_cycle`、`failed_preflight`、`unavailable_source`、`unavailable_data` 和 `license_blocked`。失败记录包含首个失败检查、最小复现命令和关联 Git 提交。

## 3. 上界与工程优化记录

每次 Oracle 运行记录 Base ASIC 周期、Oracle 周期、相对于 Base ASIC 的加速比、机制可覆盖周期、不可覆盖周期和目标。上界不足时，每个工程优化记录修改范围、优化前后软件时间、事件计数差异、质量差异以及其是否公平应用到全部变体。

硬件参数调整记录旧值、新值、允许范围、资源变化、原因和重新运行的组合。任何只改善开启目标机制路径的工程优化都不得进入正式记录。

## 4. GPU 基线记录

本地 GPU 记录原始端到端时间和阶段时间。AGX Orin 换算仅接受同套件实测向量，并记录校准套件提交、本地校准向量、Orin 实测向量、每阶段权重、换算时间和不确定性状态。缺少实测时平台结果保持 `unavailable`；公开峰值规格外推不得作为锚点、合理性判断或论文性能表项。论文表项必须能够追溯到原始测量。

## 5. 消融记录

每个模型与数据组合维护十六行消融矩阵。主列为绝对周期和 `speedup_vs_base_asic`；`speedup_vs_orin` 仅在同套件 Orin 实测可用时填写，否则为 `unavailable`。表中还包含质量差异、模块周期分解文件、配置哈希和通过状态。

完整 GALA 行与 `1111` 使用同一 `run_id` 或记录严格别名。汇总脚本验证二者周期完全一致后才生成论文数据。

## 6. Git 与产物

代码、配置、清单、文档和小型汇总进入 Git。数据集、权重、trace、重建体、分析器原始文件和大规模结果保存在仓库外，并通过内容哈希引用。每个重大进展提交同时更新当前状态、已通过验收和下一步入口条件。
