# GALA 硬件合同

## 1. 顶层数据流

关系构造器接收查询、扫描几何、高斯支持域和 CLAMP 关系模板，产生带查询键、高斯键、状态版本和执行模板的关系包。关系包更新查询状态和高斯使用索引，并进入高斯重叠引导的融合发射单元。被选任务通过高斯语义导向缓存取得状态，进入可重构计算 Pod。前向结果进入双向查询执行单元，局部消费者和伴随路径完成后，重建更新单元提交下一版本高斯状态。

所有模块通过共享 SRAM、分段互连和片外存储接口交换数据。周期模拟必须保留入口队列、输出端口、Bank 冲突、在途容量和下游反压。

## 2. 关系构造器

关系构造器接收关系种子、查询范围和高斯支持域记录，执行编译器选择的二维投影范围、精确射线覆盖、体素范围或图邻域规则。每个有效配对产生唯一 `relation_id`，并绑定 `query_id`、`gaussian_id`、`state_version` 和 `template_id`。

关系构造器的周期模型包含种子 FIFO、支持域 SRAM 访问、候选检查、有效关系写出和查询关闭事件。关系生成结束时为对应查询产生 `close`。候选数和有效关系数来自真实模型，不允许用比例采样或均值替代。

输出关系包受下游队列信用限制。下游满时，候选展开暂停，查询关闭事件不得越过尚未写出的有效关系。

## 3. 高斯重叠引导的融合发射单元

该单元包含查询状态 SRAM、更新合并器、迭代字段交换器、三条预测通路、规则排序器、冲突检查和三输入三输出发射交叉开关。

查询状态表项保存 `F(q)`、`C(q)`、`A(q)`、`Rs(q)`、`Rp(q)`、`H(q)`、`G(q)` 和 `Y(q)`。状态更新由真实事件产生的增量驱动。迭代切换时清零新 `Rs`，将本轮最终 `Rs` 复制为新 `Rp` 并置位 `H`。

预测通路计算

```text
F_hat(q) = F(q) + max(Rp(q) - Rs(q), 0)
A_hat(q) = A(q) + max(Rp(q) - Rs(q), 0)
```

`H(q)` 无效时使用已观察的精确计数，不加入历史项。预测只影响候选优先级。就绪条件使用实际计数、`G(q)`、`Y(q)` 和目标端口状态。

三级流水按以下顺序执行。

1. Forecast 读取前向、局部消费者和伴随三个队首，以编译器规则对 `F_hat(q)`、`C(q)` 和 `A_hat(q)` 排序。
2. Conflict 锁存 `q`、归约键 `k` 和目标资源 `r`，检查状态更新、归约键、后继依赖、SRAM Bank 和执行端口冲突，形成兼容掩码。
3. Issue 以兼容掩码驱动三输入三输出交叉开关，将任务写入前向、局部消费者和伴随端口寄存器。

任一候选未就绪、发生冲突或输出端口阻塞时保留在原队列。周期模型必须记录预测等待、冲突屏蔽、端口阻塞和成功融合发射次数。

## 4. 高斯语义导向缓存

每个 Pod 配置一个高斯语义导向缓存。语义驻留目录按 `(gaussian_id, state_version)` 匹配，表项保存活动槽号、关闭位、剩余使用数和活动读取数。目录命中直接访问 Active SRAM。目录未命中进入 Miss Merge，相同键的请求合并为一次片外填充，其余请求写入 Waiter RAM。

Free FIFO 提供活动槽位。填充返回后，填充仲裁器写入 Active SRAM 和目录，并唤醒等待任务。表项仅在关闭位有效、剩余使用数为零且活动读取数为零时释放。

作用域多播器比较四个队首的槽号，将相同槽号请求合并为一次 Active SRAM 读取。128 B 状态记录按两个 64 B 扇区传输到匹配计算簇。多播启动和完成分别增加和减少活动读取数。

周期模型必须逐请求模拟目录 Bank 端口、CAM 比较、Miss Merge 容量、Free FIFO、填充信用、Active SRAM Bank、两拍扇区传输、广播目标掩码和释放条件。命中率与装入次数必须由这些事件自然产生。

## 5. 可重构高斯计算 Pod

顶层包含四个 Pod。每个 Pod 包含五个计算簇。每个计算簇包含十六条 FP32 FMA、两条可配置超越函数流水、一棵十六输入归约树和四个微上下文。

FMA 被组织为四个四路算术组。三个边界选择器在前一组输出、广播高斯状态和查询操作数之间选择，使算术组能够并行或串联。执行模板由 `TRANSFORM`、`EVALUATE` 和 `COMBINE` 序列确定。

每个模板必须展开为精确的资源占用序列，包括 FMA 组、超越函数、归约树、寄存器读写和反馈。模板可以批量执行相同序列，但不能用一个平均计算周期代表不同模板或关系。

微上下文保存尚未完成关系的操作数、中间值、模板位置和目标键。上下文满时向上游反压。模板切换、反馈依赖、超越函数占用和归约树冲突均进入周期模型。

## 6. 双向查询执行单元

前向路径接收四个 Pod 的贡献并按查询编号写入六十四个查询归约 Bank。每个 Bank 交错四组部分和以覆盖 FP32 累加反馈。归约完成后将 `Y(q)` 置位并把结果写入查询 SRAM。

查询损失单元使用三十二条 FP32 FMA 执行模型规定的点式、局部图像和体数据损失。消费者的查询集合由真实依赖决定。依赖未满足或查询结果不可读时不得启动。

伴随路径包含八条重放流水。每条流水读取前向保留的关系链，将查询梯度与关系配对，并把梯度贡献送回 Pod 进行高斯归约。关系窗口直到前向、消费者和伴随均完成后释放。

周期模型必须包含查询归约 Bank 冲突、部分和反馈、查询 SRAM 端口、消费者依赖、损失单元资源、伴随重放队列、关系窗口容量和高斯所有者路由。

## 7. 重建更新单元

重建更新单元维护二十条在途高斯更新上下文。每条上下文包含参数、Adam 一阶矩和二阶矩、完整梯度、增密统计和状态版本。

更新控制 FSM 按模型规定顺序发起数值更新和集合修改。数值路径复用计算 Pod 执行 Adam 和 Split 变换。集合修改路径产生 Clone、Split 或 Prune 动作。状态写回器压紧保留记录、追加新记录、迁移或初始化优化器矩，并提交下一版本。

更新提交必须等待该高斯旧版本没有活动读取者。集合修改改变后续迭代的真实高斯数量和关系，因此必须反馈到功能执行和下一轮 trace，不能用固定高斯数贯穿完整训练。

## 8. 共享存储与片外接口

共享 SRAM 总容量、Bank 数、端口和各区域分配来自参数注册表。地址由布局规划器根据查询、关系、高斯、梯度和更新记录确定。所有 SRAM 请求使用真实地址映射到 Bank。

片外接口为八个 32 bit LPDDR5-6400 通道，总峰值带宽 204.8 GB/s。命令时序由开源 Ramulator 2 配置提供。周期执行器向内存模型提交逐请求地址、读写类型和到达周期，并使用返回周期唤醒请求。禁止用固定 DRAM 延迟或带宽除法替代命令时序。

## 9. 禁止的周期捷径

- 不得用模块利用率乘峰值吞吐计算完成周期
- 不得用平均关系数代替关系 trace
- 不得用预设命中率生成缓存结果
- 不得忽略满队列、端口冲突、Bank 冲突或回压
- 不得让预测结果直接确认查询完成
- 不得在伴随完成前释放关系或高斯状态
- 不得在更新提交前改变状态版本
- 不得把软件事件缓冲区计作无限硬件队列

## 10. 资源包络与可调边界

硬件合同冻结模块边界、接口和顶层资源包络，不冻结每个内部表项的初始估计值。实现者可以依据真实 trace 和模块级校准调整非核心队列、表项、Bank 数、流水寄存和 SRAM 分配。调整必须在正式多任务评测前冻结，并由同一配置覆盖所有模型、数据集和消融组合。

顶层资源包络如下。

| 资源 | 上限或固定组织 |
| --- | --- |
| 计算 Pod | 4 个，每个 5 个计算簇 |
| FP32 FMA | 320 条 |
| 超越函数流水 | 40 条 |
| 共享 SRAM | 2.75 MiB |
| 融合发射候选宽度 | 3 |
| 片外接口 | 8 个 32 bit LPDDR5-6400 通道 |

可调项包括查询状态容量与 Bank 组织、活动高斯记录数、Miss Merge 容量、关系窗口、非核心 FIFO 深度、共享 SRAM 区域划分和模块内部流水寄存。不得通过增加 Pod、计算簇、执行通路、片上 SRAM 总量、发射宽度或片外通道获得目标加速比。

每次硬件调整记录变更前后数值、原因、受影响模块、字节预算、端口预算、执行通路数量和所有消融配置的统一配置哈希。模拟器不输出面积或功耗指标，但必须验证资源闭合。
